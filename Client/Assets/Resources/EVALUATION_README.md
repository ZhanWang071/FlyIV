# Evaluation System for API-based vs General LLM Comparison

## Overview
This evaluation framework compares the performance of:
1. **API-based System**: LLM generates single-line API calls
2. **General LLM**: LLM generates complete C# code files

## Files Created

### 1. Test Cases (`TestCases.json`)
- 30 test cases covering all available APIs
- Each test includes: id, description, input prompt, expected API, and data file

### 2. Prompts
- **TestPromptAPI.txt**: Simplified prompt for API-based system (generates API calls only)
- **TestPromptGeneral.txt**: Prompt for general LLM (generates complete C# code)

### 3. Evaluation Script (`Evaluation.cs`)
Main evaluation controller with the following features:
- Switch between API and GeneralLLM modes
- Configure different LLM models
- Automatic test execution on all 30 cases
- Timing measurements for each stage
- Success/failure tracking
- JSON result export

## Usage

### Setup
1. Add `Evaluation.cs` to a GameObject in your scene
2. Assign the `ActionExecutor` reference in the Inspector
3. Configure test mode and model name

### Running Tests

#### Option 1: API-based System Test
```
1. Set testMode = API
2. Set modelName (e.g., "gemini-3-flash-preview")
3. Right-click Evaluation component → Run All Tests
```

#### Option 2: General LLM Test
```
1. Set testMode = GeneralLLM
2. Set modelName (e.g., "gpt-4o")
3. Right-click Evaluation component → Run All Tests
```

### Results
Results are automatically saved to `Assets/Logs/Evaluation_{Mode}_{Model}_{Timestamp}.json`

Each result includes:
- `test_id`: Test case identifier
- `description`: Test description
- `input`: User input prompt
- `use_api`: Whether API mode was used
- `model`: LLM model name
- `llm_time`: Time for LLM to generate code (seconds)
- `execution_time`: Time to execute the code (seconds)
- `total_time`: Total time (seconds)
- `success`: Whether execution succeeded
- `error_message`: Error details if failed
- `generated_code`: The code generated by LLM

### Console Summary
After all tests complete, a summary is printed:
```
Mode: API / GeneralLLM
Model: gemini-3-flash-preview
Success Rate: 28/30 (93.3%)
Avg LLM Time: 1.23s
Avg Execution Time: 0.45s
Avg Total Time: 1.68s
```

## Test Coverage

The 30 test cases cover:
- **CREATE**: 2D bar/line/pie, 3D bar/scatter (5 cases)
- **DELETE**: Remove visualizations (1 case)
- **UPDATE**: Modify element values (1 case)
- **DELETE_ELEMENT**: Remove elements (1 case)
- **APPEND_SINGLE**: Add single data point (1 case)
- **APPEND_SERIES**: Add data series (1 case)
- **HIGHLIGHT**: Highlight elements (1 case)
- **CHANGE_SERIE_COLOR**: Change series color (1 case)
- **CHANGE_DATA_COLOR**: Change data color (1 case)
- **POSITION**: Set position (1 case)
- **ROTATE**: Set rotation (1 case)
- **SCALE**: Set scale (1 case)
- **ORIENT_TO**: Orient to object (1 case)
- **ADAPT_POS**: Adapt position to object (1 case)
- **EMBED**: Embed on surface (1 case)
- **LAYOUT**: Arc/grid layout (2 cases)
- **DATA_TRANSFORM**: Split data (1 case)
- **Complex workflows**: Multi-API combinations (7 cases)

## Data Analysis

To analyze results across multiple runs:
1. Collect JSON files from `Assets/Logs/`
2. Compare metrics:
   - Success rate: API vs General
   - Average times: LLM generation, execution, total
   - Error patterns: Which tasks fail more often
3. Calculate aggregate statistics per model and mode

## Notes

- Each test has a 1-second delay to avoid API rate limits
- General LLM mode extracts code from markdown code blocks
- API mode directly passes output to ActionExecutor
- Failed tests log error messages for debugging
- All timing uses high-precision Stopwatch

## Troubleshooting

**Issue**: Tests fail with "TestCases not found"
- **Solution**: Ensure TestCases.json is in Assets/Resources/

**Issue**: Prompt not loading
- **Solution**: Check TestPromptAPI.txt and TestPromptGeneral.txt are in Assets/Resources/prompts/

**Issue**: General LLM code fails to execute
- **Solution**: Check generated_code in results JSON, verify C# syntax and Unity API usage

**Issue**: API calls not executing
- **Solution**: Verify ActionExecutor reference is assigned and Skills folder exists
